# 0911 정전복구 변경 기록

기준: `mod/blackout`, `370182fd955bc6a3c71a3426fbb00217109b7f8b`.
요구사항은 `develog/0911.md`, 통신 비교 기준은 제공된 `SerialComm.java`,
`AbstractSerialRunnable.kt`, `SerialMain.kt`, `Util.kt`다.

## 시간 정책

발효의 고정 시간은 **정전 전 실제 진행 시간 + 복구 후 남은 시간 = 설정 시간**으로
해석했다. 원본 `SerialComm`의 `elapsed = configured - blackoutRemaining`과 일치한다.
정전 시간을 발효 경과로 차감하거나 발효를 설정 시간 전체부터 다시 시작하지 않는다.

| 정전 전 단계 | 복구 처리 | 완료시각 |
| --- | --- | --- |
| 냉동 | 발효1·2의 전체 시간을 먼저 확보하고, 남는 시간에서 해동과 냉동을 배분 | 가능한 경우 유지 |
| 해동 | 발효1·2를 확보한 뒤 남는 시간만 해동 | 가능한 경우 유지 |
| 냉동·해동 중 예정 완료까지 발효 시간조차 부족 | 냉동·해동을 건너뛰고 발효부터 시작 | 발효 시간을 확보할 만큼 연장 |
| 발효1 | 저장된 발효1 잔여시간 + 발효2 전체 시간 | 복구시각 + 두 단계 잔여시간 |
| 발효2 | 저장된 발효2 잔여시간 | 복구시각 + 잔여시간 |

0분인 단계에는 시작 명령을 보내지 않는다. 다음 남은 단계부터 재개하며, 전부 0이면
완료 상태로 복구한다. 계산은 `blackout_recovery.c`에 분리했다.

## 수정 원인과 동작

- 복구가 읽던 `originComplete*`는 기존 코드에서 완료 화면에 도달해야 저장됐다.
  따라서 이전 운전/기본값이 이번 운전의 복구 계산에 들어갈 수 있었다.
  시작 시 원본 완료시각도 저장하고, 복구는 현재 운전에 속한 `CurrentComplete*`를 읽는다.
- `STATUS`의 명령 바이트를 0번으로 센 `payload[17/18]`은 경과시간,
  `[19/20]`은 잔여시간이다. C 구현이 `[19/20]`에 총 설정시간을 보내던 것을 수정했다.
  예: 총 14:01, 잔여 10:26이면 각각 **03:35 / 10:26**을 전송한다.
- 복구할 단계를 `first_send`로 명시적으로 시작한다. 원하는 단계가 확인되기 전에는
  이전 운전의 응답을 새 시작 명령으로 되돌려 보내지 않는다.
- 복구 표식 `[21]=0x11`과 확인 응답 `[14]=0x21` 처리를 유지한다.
- 모든 단계에 걸친 잔여시간 감소 제한을 제거했다. 해동 0분에서 발효1 180분으로
  넘어가는 정상적인 시간 증가가 허용된다. 단계와 잔여시간은 같은 수신 응답에서 저장한다.
- UI 타이머가 MCU보다 먼저 단계나 완료 상태를 확정하던 처리를 제거했다.
  표시, 재송신, 복구 저장은 승인된 MCU 상태를 함께 사용한다.
- `CONDATA`의 발효·건조 필드는 `온도/시간/분/습도` 순서다.
  `온도/습도/시간/분`으로 읽던 C 인덱스를 원본의 `SaveValue2` 매핑과 맞췄다.
  복구 중에는 이미 복원한 설정을 `CONDATA`로 덮어쓰지 않는다.
- `00:00` 완료시각과 날짜를 그대로 전송한다. 원본에 없는 08:00 강제 보정에 관한
  오래된 주석을 제거했다. 자정이라는 이유만으로 미설정으로 취급하지 않는다.

검증한 항목:

- 냉동·해동 유지/단축/건너뛰기, 완료시각 연장, 발효1·2 중 복구, 재정전, 0분 단계.
- 날짜를 포함한 자정 완료 패킷, 윤일 경계 계산.
- 복구 STATUS 전체 페이로드와 프레임 체크섬, 복구 표식 확인.
- 다음 단계의 잔여시간 증가, 오래된 단계 응답 거부와 재송신 방지.
- 복구 요청 확인 전 잔여시간 보존, 짧은 STATUS 거부.
- 완료·건조·수동·정지 전송, 기존/확장 CONDATA 필드 순서.

호스트 테스트와 AddressSanitizer/UndefinedBehaviorSanitizer 검증을 통과했다.
이 실행 환경에서는 LeakSanitizer가 프로세스 정보를 읽을 수 없어
`ASAN_OPTIONS=detect_leaks=0 bash tests/blackout/run.sh`로 실행했다.
UI 파일과 `main_activity.c` 전체를 이 호스트 테스트에서 컴파일한 것은 아니다.

복구 잔여시간은 기존 프로토콜처럼 분 단위다. UART 경로의 저장 요청은 단계 변경 시와
30초 주기로 처리하며, 실제 저장은 기존 `settings_save_dirty()`의 지연 저장 방식을 따른다.
전원 차단 직전의 초 단위 진행 상태까지 보장하는 변경은 아니다.
